### Errors and ownership

`Error` has a stable category plus bounded numeric context: Bounds, InvalidByte, Overflow, InvalidEncoding(codec, offset, reason), ResourceLimit(dimension, limit, used, requested), Io(operation, errno, completed), Unsupported(capability), SourceChanged, UnsafeNamespace, ResidualWork, InternalInvariant. Do not store input text or arbitrary OS strings in an unbounded error. Later CLI maps errors to DESIGN.md exit codes; core tests assert variant and fields.

`Budget`, `Reservation`, `OwnedBytes`, `ScalarChunk`, and `ShaState` are affine Type wrappers. All operations return ownership of unchanged/partially consumed inputs and budget on failure, or explicitly consume them through a disposal path. Do not use IO.die inside library helpers: it bypasses reservation/handle cleanup. Type affinity prevents double use, not silent abandonment, so audit explicit disposal/settlement paths and test live balances. Module visibility is not a security boundary: documented API plus repository lint/test checks forbid raw allocation/Array access outside trusted implementation modules.

### Checked arithmetic and ranges

`add`, `sub`, `mul`, `ceil_capacity`, checked byte conversion return Result. Add uses `b <= MAX-a`; subtract uses `b<=a`; multiply treats zero separately then uses `a<=MAX/b`. Guard depth before shift; lengths never exceed UINT32_MAX (thus strictly below 4 GiB).

`Range(originId,start,end)` is validated against its parent/source; `Cursor(range,pos)` satisfies start<=pos<=end. `take(n)` checks pos<=end and n<=end-pos before producing child range and advancing cursor. `subrange(offset,n)` checks offset<=length and n<=length-offset before computing absolute endpoints. Reject range/cursor from another source owner, parent escape, reversed endpoints, and truncated reads; zero-length at end succeeds. `read_u8/u16_le/u16_be/u32_le/u32_be`, `skip`, and `remaining` operate on these checks. No signed arithmetic emulation through wrapping subtraction.

Core cursor uses an owned <=65536-byte window with absolute base/valid length; abstract file spans do not authorize access to missing bytes. Crossing a window returns NeedMore/explicit refill status at the stream adapter, never indexes wrapped storage. Provide a small fixed-width cross-window assembler for up to four bytes; #2 tests feed synthetic windows without OS IO.

### Buffers

`OwnedBytes` owns Array<U32>, logical length, capacity, origin, live reservation. Physical payload is not a packed byte vector: each value is U32 constrained to 0..255. Capacity <=65536; length<=capacity. Empty buffers have a documented minimum capacity/charge. `new`, `put/get`, `append`, `clear/reuse`, `drop`, bounded `copy_range` reserve before allocation and charge accesses before work. Ordinary slices are validated descriptors, not hidden clones; access threads the owner. A copy has its own reservation while source remains live. No implicit String/List conversion. For any unavoidable C boundary List representation, reserve its separately measured overlapping lifetime before requesting IO; bound it to a chunk, consume it sequentially and validate returned length/bytes.

`ScalarChunk` uses Array<U32> of valid Unicode scalars with a separate measured charge and explicit bounded capacity. Codecs stream scalar chunks; they do not build an unbounded linked String or one allocation per character. Callers needing a whole logical string later must use a separately budgeted builder.

### Six-budget accounting, normative

One affine budget is threaded across every input/entry/phase of a run. Six independent dimensions: input bytes, expanded bytes, output bytes, logical referenced bytes, live allocation charge, cumulative byte-work. Limits and arithmetic are U32 and capped by tested profile; logical defaults come from DESIGN.md, not a claim that maximum-sized fixtures all fit memory. Per-file/format caps are additional checks and never reset aggregate counters. A separate provenance verification invocation starts a fresh run; plan/apply within one invocation does not.

Input: charge bytes actually acquired into the authoritative snapshot once; re-reading snapshot charges work, not new input. Expanded: charge actual produced decompressed bytes on every decompression, including later audit; future decompressor must use this API. Output: charge bytes successfully emitted as final artifacts once, including metadata/report files; snapshot scratch copies are input, not output. Retry within one write operation commits only newly successful bytes. Rebuilding a discarded output counts again as work and counts emitted bytes again in cumulative output; do not reset on failure. Logical: caller declares each referenced logical byte length before resolution, charging every reference even for aliases; caching never makes logical references free. Live: reserve conservative representation cost before allocating, return only when owner/transient lifetime ends. Work: every production pass charges actual byte visits, including snapshot copying, hashing, scan, decode, encode, verification and repeated aliases; no entry resets.

Define work precisely in API docs/tests: reading or writing a byte in owned storage costs one; copying n bytes costs n reads+n writes; hashing n input bytes costs n input visits, SHA's fixed 64-round per-block arithmetic is not 64 additional byte visits; decode costs input-byte reads plus output scalar's canonical UTF-8 width on emission; encode costs scalar canonical UTF-8 width on inspection plus output-byte writes. Chunk-boundary retries must not charge unvisited bytes or reread already consumed prefixes without charging. OS read/write copying contributes transferred bytes at that boundary, separately from codec/hash visits. Invalid-byte validation scans are real visits. Internal padding/schedule processing in SHA has bounded fixed per-block cost and does not count as input/output bytes; document it separately in performance statistics. Cursor metadata/range arithmetic costs no byte-work. These are normative logical costs, not CPU-instruction counts or RSS.

Reservation protocol: `reserve_many` checks all dimensions first, then returns budget+affine ticket; failure leaves used/held unchanged. For consumable counters maintain used and held, with used+held<=limit checked without overflow. Execute only while enough held exists, settle actual successful amount and cancel unused remainder; consumed work/bytes never refund. Live reservation stays attached to owner until destruction; partial allocations and failure paths release only objects actually disposed. Invalid release/double settlement is InternalInvariant. Preflight is a reservation, not a second consumption. Short IO reserves requested maximum then settles actual transferred bytes, including prefix-before-error; errors still prevent success. Tests exercise aggregate across multiple entries, multiple phase scans, reservation competition, zero request, exact limit, +1, overflow and failure before observable allocation/work.

### Strict codecs

UTF-8 decoder carries bounded partial scalar state across chunks with absolute error offset. Accept ASCII including NUL; 2/3/4-byte forms must satisfy minimum scalar, continuation syntax, no D800–DFFF and <=10FFFF. Reject C0/C1, F5–FF, stray continuation, invalid E0/ED/F0/F4 second-byte ranges, truncated final sequence. Preserve BOM as U+FEFF at core level; field/XML policy is downstream. Encoder rejects invalid scalars, does not normalize, replace, guess encoding, or treat NUL as terminator. Feed returns consumed count and state; finish rejects partial sequences; insufficient output capacity yields explicit resume without repeating work.

Windows-1252 policy is strict mapping: ASCII/0xA0–0xFF identity, defined 0x80–0x9F mapping table; undefined 81/8D/8F/90/9D are decode errors, not Latin-1 controls. Encoding accepts only exact reverse mapping; U+0081 etc and all unmappable scalars fail. All 251 defined bytes round-trip; the five holes have negative tests. This resolves the otherwise ambiguous term CP1252 explicitly in docs and tests.

### SHA-256

Implement raw-byte streaming SHA-256 in Bend only: eight U32 words, 64-byte pending block, 16-word rolling schedule (or fixed 64-word schedule if measurement justifies it), constants, guarded rotates, intentional modular additions. State tracks total byte count in hi/lo U32 limbs; checked conversion to 64-bit bit length rejects values beyond SHA's domain. File cap still remains U32. `init/update/finalize` consume/return state and budget; finalize consumes state so update-after-finalize is unavailable in supported API. Digest is exactly 32 raw bytes; hex is a separate bounded formatter. Canonical plan encoding/digest is out of scope. Reserve SHA state/workspace before initialization and retained/output buffers before finalization; padding allocation and every owned temporary remain in live charge.

## #3 implementation and API

Files: `host/io.bend`, `host/native/fs.c` (small reviewed effects only), `host/snapshot.bend`, `host/staging.bend`, `tests/host/`, `tools/host/`, `docs/host/{contract,capabilities}.md`. Runtime extension source and build manifest are hashed alongside generated C/binaries. No silent subprocess converter or shell publication fallback.

### Effect surface

Opaque affine DirHandle/FileHandle and scalar metadata records. OS dev/ino/size/time fields cross ABI as checked hi/lo limbs (seconds signed representation explicitly specified), never truncated U32 inode identifiers. File size over UINT32_MAX rejected before copying. Keep underlying descriptor integers private.

- `open_root` / `open_dir_at(parent, component)` using O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC; open paths component-by-component from held root/explicit trusted anchor. Reject NUL, empty interior components, '.', '..', '/' in a component. Absolute input path handling and safe display of non-UTF8 bytes are distinct; paths use raw bytes, never lossy decoding. Final names are validated bounded components generated internally where appropriate.
- `open_regular_at` with O_RDONLY|O_NOFOLLOW|O_CLOEXEC|O_NONBLOCK, then fstat regular type; nonblocking prevents FIFO/device blocking before type rejection. Do not read nonregular handles. Return handles on recoverable errors or consume/close them explicitly.
- `mkdir_exclusive_at(0700)`, `create_regular_exclusive_at(0600)` with O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC. Enforce/recheck actual mode and uid after creation, despite umask/default ACL. fchmod only newly owned objects, not pre-existing ancestors. Record identity immediately.
- `fstat`, `stat_entry_nofollow`, `read_acl_fd`, `list_entries_fd`, `pread_chunk`, `pwrite_chunk`, `fsync_file`, `fsync_dir`, `close_checked`, `rename_noreplace_at`, `unlink_recorded_at`, `rmdir_recorded_at`. Bounded listings/ACL buffers have explicit maximum and budget; oversized metadata fails closed before allocation.
- Read effect performs one pread (retry EINTR), returning bytes/count+EOF/error. No accumulation that loses a later error. Bend exact-read loop handles short/zero/EOF and sticky failure. Offset+request checked first. Write effect returns transferred prefix/error; Bend loops on positive shorts, zero with remaining => error, EINTR retry bounded by outer timeout. Completion is never inferred from final size alone.
- Close consumes handle even on error on Linux; do not retry close on EINTR/EIO and risk closing a reused descriptor. Save errno immediately. File fsync precedes checked close; no successful artifact marker after either fails. Directory fsync and no-replace rename capability failures are explicit, with no check-then-rename fallback.

### Namespace and ACL policy

Output parent and every traversed ancestor must be root- or effective-uid-owned and have no group/other namespace write permission. Reject sticky/shared-writable directories even when user owns child; default /tmp is not a valid production root under this conservative policy. CI creates a root-owned nonshared ancestor and user-owned secure work parent. Input paths require no-follow component traversal and regular files; do not imply input ancestor write policy alone prevents same-user input changes.

Use fd-based Linux ACL inspection (bounded fgetxattr of system.posix_acl_access and system.posix_acl_default, with tested parsing of Linux ACL xattr format; alternatively explicitly locked libacl only after build dependency review). Validate version, entries, IDs, mask rules and malformed/duplicate fields. Conservative initial policy may reject all extended access/default ACLs, including read-only grants, rather than miscompute effective rights; document this restricted support. Missing ACL (ENODATA) is accepted with mode checks. Inspection denied, malformed, unexpected errors, or unsupported ACL detection fails closed. ENOTSUP may only mean no ACL on a specifically tested/allowlisted filesystem profile with independent evidence, not a generic permission bypass. Reject unsafe default ACL on traversed/creation parents; recheck each actually created directory/file. Capture filesystem type and capability probes; network/FUSE/overlay/unknown filesystem transactional use remains disabled unless separately validated. Capability support is per actual output filesystem, not uname alone.

Open and retain descriptors through the operation; later effects never reconstruct paths. Trusted owners must not mutate permissions/names concurrently. Threat model protects against unrelated nonprivileged accounts, excludes same-uid/admin/mount-namespace attacks. Identity check immediately before rename is diagnostic, not protection against a writable source parent.

### Snapshot state machine (Bend)

`capture(sourceHandle, stage.snapshotsDir, budget, retainPolicy)`:
1. fstat before copy; record dev/ino/type/size/mtime/ctime nanoseconds, reject unsupported size/nonregular. Compare supplied source handles to detect aliases by dev+ino; reject duplicate input identities where distinct inputs required. Reject source identity colliding with owned scratch artifacts/output objects. A harmless unrelated hard link is not itself a symlink, but input role aliases must be detected explicitly.
2. Reserve input budget for known size and bounded live/IO/work windows. Exclusively create private snapshot outside publish child. Copy in <=64KiB chunks with custom transparent reads; hash exactly successfully copied raw bytes with #2 SHA; loop short writes, meter actual consumption. EOF before expected size or bytes beyond expected size => SourceChanged. No recovery that silently joins prefixes after EIO.
3. fstat original handle again and compare all recorded stable fields (not atime, which reading can change). fstat snapshot expected length/identity; fsync and checked-close writer. Reopen snapshot read-only through held parent and compare identity. Compute read-back Bend SHA to check recorded copy digest and size, with work budget; retain read-only handle. The digest names captured bytes, not an atomic OS point-in-time image; equal metadata cannot defeat adversarial same-user races, explicitly outside guarantee.
4. Return immutable metadata/digest + snapshot handle/catalog entry. Future parse/hash/audit reads only this snapshot. Original is never opened writable. On failure dispose owned temporaries and invoke guarded cleanup; report residual work instead of hiding cleanup failure behind original error.

Retention is an explicit policy: default remove snapshots at normal/error cleanup; retain only in a separately exclusively created private directory selected by caller, never in publish child. Explicit retention applies to successfully verified captures even when a later run step fails. A capture that fails copy, metadata, sync, close, or read-back verification is never reported as a valid retained snapshot; safely owned incomplete captures may be discarded, while uncertain entries are preserved and reported as unverified residuals. Completed captures and incomplete captures have distinct ledger states. Retention directory undergoes the same namespace/ACL checks; existing directory target is rejected. If retention movement requires cross-FS, reject in initial implementation rather than unsafe copy fallback; document this restriction. #3 supplies API/tests, not invented full CLI support. Crash/kill cannot promise cleanup; residual identifiers and recovery restrictions are documented.

### Staging and cleanup

Create unpredictable unique private parent as a child of retained safe output parent (secure random OS bytes + exclusive mkdir collision handling), then snapshots/ and publish/ children. Verify uid/mode/ACL/dev and recorded identities; same filesystem established by topology plus fstat st_dev and actual rename capability tests, no symlink/mount shortcut. Keep private-parent and publish dirfds. Reserve bounded creation ledger before each creation; ledger records parent token, component, dev/ino/type, lifecycle. Add entry before subsequent fallible work; on creation succeeded but identity capture failed mark uncertain and leave residue, never guess.

Retention ownership state machine: `Verified -> RetentionAttempted -> Retained`, `RetentionNotTransferred`, or `RetentionUnknown`. Before invoking a no-replace retention move, freeze scratch deletion eligibility for the source directory and every descendant, including entries reachable through old retained dirfds. On confirmed transfer, synchronously transfer the directory and its complete descendant ledger to a non-deleting retention ledger and mark them `Retained` **before any subsequent fallible operation**, including fsync, close, logging or reporting. Retained is terminal for automatic cleanup: closing an old or new descriptor never authorizes unlinking its contents. This is an ownership transfer, not just a pathname update. Subsequent fsync/close/report failure records retention durability/reporting failure but cannot restore scratch eligibility. Reserve all state/ledger transition resources before the move, so the success-path ownership transition needs no fallible allocation.

If the move definitely did not execute, reconcile source/destination identities and mark `RetentionNotTransferred`; explicit retention failure leaves verified captures as protected residuals and reports that the requested retained destination was not established. Do not silently discard those requested captures. If the move outcome is uncertain, mark `RetentionUnknown` and keep the entire possibly transferred subtree excluded from deletion and blind retry. Reconcile using held descriptors and authoritative no-follow identities in the trusted namespace. Only a proven matching destination permits `Retained`; absence of the old name alone does not. If reconciliation cannot establish ownership/location, leave all potentially affected entries untouched and report residual/uncertain retention, not successful retention. Existing destination objects are never adopted, overwritten or deleted. Scratch-only unrelated entries remain eligible for safe cleanup; retained/residual handles may be checked-closed and live reservations released when their in-memory owners are disposed, without deleting on-disk data or double-settling reservations. A retained directory is never added to the scratch ledger again merely because its descriptor remains open.

Lifecycle for publication (separate from retention): Created -> Verified -> PublishAttempted -> Published, NotPublished, or Unknown. Primitive tests exercise no-replace rename; integration is deferred. Rename success permanently excludes published child from cleanup, even if later parent fsync fails. Injected uncertain outcome must reconcile retained source descriptor and no-follow source/destination identities in trusted namespace; only classify Published when destination is proven same recorded object, otherwise Unknown. Unknown blocks all potentially relevant deletion/retry and reports residue; missing source alone proves nothing. Never delete final destination, including an object another process won in a race.

Cleanup uses held descriptors and only deletion-eligible scratch ledger entries, bottom-up. `Retained`, `RetentionAttempted`, `RetentionUnknown` and protected retention-failure residuals, together with all their descendants, are excluded before enumeration or deletion, regardless of the names or old dirfds that still reach them. Bounded enumeration first checks that no unexpected entries exist; any unknown name/type/identity, hard-link anomaly for created files (nlink!=1), replaced directory, or changed trust state stops that subtree and reports residue. Never recurse into unrecorded directories or follow symlinks. Use unlinkat for exact recorded regular files and AT_REMOVEDIR for exact empty recorded dirs only after no-follow identity check. Trusted private namespace is the race protection; comparison alone is not. Removing private parent's public name requires safe held outer parent and matching identity; otherwise leave it. Original inputs and published bundle can never enter the deletion ledger.
